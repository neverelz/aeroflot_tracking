# 🛫 Аэрофлот — Telegram-трекер цен

Проект состоит из двух процессов:

- `bot.py` принимает заявки пользователей в Telegram;
- `tracker.py` периодически проверяет цены по сохранённым заявкам и отправляет уведомления.

В заявке пользователь вводит только города начала и конца маршрута, выбирает IATA-коды из каталога направлений Аэрофлота, отмечает в календаре одну дату или диапазон до 31 дня, задаёт максимально допустимое количество пересадок, время стыковок и желаемую цену. Промежуточные города программа подбирает автоматически среди вариантов Аэрофлота. Для диапазона бот создаёт отдельную задачу на каждый день, а в интерфейсе показывает их как одну заявку.

## Установка

Используйте Python 3.10–3.12 (версии зависимостей проекта не рассчитаны на Python 3.14).

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
playwright install chromium
```

Создайте `.env` из примера и заполните токен, полученный у `@BotFather`:

```powershell
Copy-Item .env.example .env
```

```env
TELEGRAM_BOT_TOKEN=1234567890:ваш_токен
CHECK_INTERVAL=3
MIN_CHECK_GAP_SECONDS=10
QUEUE_POLL_SECONDS=5
```

Новая заявка обнаруживается в течение `QUEUE_POLL_SECONDS` и проверяется один
раз сразу, как только подходит её очередь. Затем каждая дата заявки проверяется
раз в `CHECK_INTERVAL` часов. Между стартами любых двух проверок — в том числе
заявок разных пользователей — выдерживается минимум 10 секунд. Если заявок
много, они чередуются по одной дате от каждой заявки.

## Запуск

### Docker Compose

Для запуска всего проекта нужен Docker с Compose. Создайте `.env` из примера, укажите `TELEGRAM_BOT_TOKEN`, затем выполните:

```powershell
docker compose up --build -d
```

Команда поднимет два контейнера: `bot` принимает заявки, а `tracker` проверяет цены в headless Chromium. Оба контейнера автоматически перезапускаются и используют общий Docker volume `aeroflot_tracking_data`.

Образ собирается на базе `python:3.10-slim-bookworm`; Chromium устанавливается из репозитория Debian. Доступ к `mcr.microsoft.com` и скачивание браузера через Playwright CDN не требуются.

Полезные команды:

```powershell
# Логи обоих сервисов
docker compose logs -f

# Состояние контейнеров
docker compose ps

# Остановить проект, сохранив данные
docker compose down

# Пересобрать после изменения кода
docker compose up --build -d
```

Если в старой установке использовался bind mount `./data:/app/data`, его можно перенести в named volume после первого запуска новых контейнеров:

```bash
docker compose stop bot tracker
docker compose cp ./data/. bot:/app/data/
docker compose start bot tracker
```

Исходный каталог `./data` при этом не удаляется. Трекер также не останавливается
из-за недоступности `tracker.log` или `prices.csv` и продолжает писать основной
лог в `docker compose logs`.

### Без Docker

Откройте два терминала с активированным виртуальным окружением.

В первом запустите Telegram-бота:

```powershell
python bot.py
```

Во втором запустите периодическую проверку цен:

```powershell
python tracker.py
```

Для однократной проверки всех заявок:

```powershell
python tracker.py --test
```

При локальном запуске режим браузера задаётся переменной `HEADLESS` в `.env`. В Docker Compose всегда используется `HEADLESS=true`.

## Команды бота

После `/start` бот показывает постоянное кнопочное меню. Во время заполнения заявки меню временно заменяется кнопкой «Отменить», а после завершения появляется снова.

- `/start` — приветствие;
- `/new` — создать заявку;
- `/requests` — посмотреть, изменить или удалить свои заявки;
- `/airports` — подсказка по аэропортам;
- `/menu` — вернуть главное кнопочное меню;
- `/cancel` — отменить текущее заполнение;
- `/help` — справка.

Город можно вводить по-русски или по-английски. Бот показывает кнопки только для кодов из встроенного каталога направлений Аэрофлота; произвольный трёхбуквенный код сохранить нельзя. Для Москвы первым предлагается общий код `MOW`, затем конкретные аэропорты. Даты выбираются во встроенном календаре с переключением месяцев.

После дат выбирается максимум пересадок: только прямые рейсы, до одной или до двух. Для маршрутов с пересадками доступны удобные стыковки от 1 ч 30 мин до 5 ч, любые варианты Аэрофлота до 12 ч либо собственный диапазон. Ночные стыковки и смена аэропорта исключаются. В карточке каждой заявки доступны кнопки изменения маршрута, дат, пересадок и ценового порога.

## Хранение данных

При локальном запуске заявки сохраняются в `tasks.json`. В Docker файлы `tasks.json`, `check_state.json`, `prices.csv` и `tracker.log` находятся в volume `aeroflot_tracking_data`, смонтированном как `/app/data`. `check_state.json` хранит время последней проверки каждой задачи и глобального десятисекундного интервала. Бот записывает JSON атомарно, поэтому трекер не увидит частично сохранённый файл.

Пример задачи:

```json
{
  "request_id": "a1b2c3d4",
  "chat_id": "123456789",
  "origin": "SVO",
  "dest": "AER",
  "date": "14.08.2027",
  "threshold": 15000,
  "max_stops": 1,
  "connection_mode": "comfortable",
  "min_connection_minutes": 90,
  "max_connection_minutes": 300,
  "avoid_overnight": true,
  "allow_airport_change": false
}
```
